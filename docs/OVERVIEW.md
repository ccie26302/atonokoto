# あとのこと ― 何をするもので、どう動いているか

2026-09-14 時点の実装に基づく。数値はすべて実測。文書上の設計は `DESIGN.md`、構成は `ARCHITECTURE.md`、脅威と対策は `THREAT_MODEL.md` にある。ここはその三つを一つに要約したもの。

## 1. 一言で

人がいなくなった後、その人のデジタルの持ち物（サブスク、写真、アカウント）を、生前に本人が決めたとおりに「止める・渡す・報告する」AI エージェント。Google Cloud 上で動く。

## 2. 誰の、どんな困りごとか

- 本人: 自分に何かあったとき、サブスクが払われ続け、写真は誰にも渡らず、SNS は残る。家族に全部のパスワードを預けるのは危険で、かといって整理する時間も気力もない。
- 家族: 何を契約していたか分からない。解約しようにも入れない。どこまで触っていいか分からない。
- 既存の答えの限界: Google の「アカウント無効化管理ツール」は Google アカウントの中だけを扱い、第三者サービスの契約や「何を誰に」という遺志は扱わない。「本人が死んだかどうか」を機械が決めるのは危険で、誰も引き受けていない。

対象は gmail.com の個人。Google Workspace は前提にしない。

## 3. 設計の芯（守っている約束）

1. 死を確定しない。エージェントは「沈黙している」としか言わず、最後は人（確認者 2 人）が答える。
2. 判断の床は縮まない。30 日で「気にかける」、60 日で「確認者に問う」、猶予 14 日、発火後 7 日のブレーキ。この日数は決定的な状態機械が持ち、LLM は「説明」と「延ばす提案」しかできない。
3. 遺志は本人だけが塗る。一言の解釈は提案で、本人が押すまで塗らない。パスワードを渡す遺志は設計上作れない。
4. 執行は決定的なゲートを通る。遺志に無いことはしない。確認者 2 人未満なら通さない。依存が残るハブ（Google アカウントなど）は最後。
5. 秘密は enclave の中でしか開かない。預かった資格情報はブラウザで公開鍵により封印し、復号できるのは attestation を通った実行イメージの digest ひとつだけ。
6. 消せない記録。ゲートの判定はハッシュ鎖で追記専用のバケットへ。監査ログは 400 日。
7. 同意は分ける。棚卸し（受信箱の本文、一回きり）と、見張り（メタデータ、毎日）の同意は別。

## 4. 本人から見た流れ

1. Google でログインする（読み取りだけのスコープ）。
2. 「棚卸し」を押すと、受信箱を一度だけ読み、契約・アカウント・依存関係を星図に描く。暗い星は「使っていないのに払っている」。読み終えたらトークンは捨てる。
3. 星ごとに「渡す・消す・残す」を塗る。プラン・金額・ログイン経路も直せる。「一言で」に「サブスクは全部止めて、写真は妻に」と書くと提案が出て、「この通りにする」で塗られる。曖昧なら聞き返す。
4. 確認者を 2 人以上登録する。あとがき（地図に書けないこと）を書く。任意で、解約に使う資格情報を封印して預ける。
5. あとは何もしない。以後は毎日 1 回、裏で見張りが動く。あとのことへのログインは合図にしない（本人に何かをさせる方向に寄るため）。

## 5. 見張り（毎朝 06:30、Cloud Run ジョブ）

### 何を見るか（本文は読まない）

| 源 | 取るもの | 同意 |
|---|---|---|
| メールの既読・送信 | 受信・送信の日時。件名や本文は取らない | gmail.metadata |
| 買い物・予約・振込の通知 | 差出人ドメインと件名の型で「本人が今買った・予約した・振り込んだ」だけを拾う。記録に残すのは店と日付と件数のみ | 同上（追加なし） |
| Drive の活動 | 本人が編集した日時 | drive.activity.readonly |
| 予定の変更 | 更新日時。前後 30 日の題名は説明の手掛かりにだけ使う | calendar.readonly |
| YouTube | 高評価とチャンネル登録の日時 | youtube.readonly |
| 足したサービス | GitHub、Zenn、Qiita、Bluesky、note、Mastodon、Wikipedia、AtCoder の公開物の日付。Lichess、Chess.com、Stack Overflow のサイトを開いた日。Letterboxd の観た日 | 認証なし（公開 ID だけ） |

通知メールで拾う店は Amazon、楽天市場、Yahoo!ショッピング、メルカリ、ヨドバシ、ZOZOTOWN、ユニクロ、Uber Eats、出前館、マクドナルド、スターバックス、PayPay、モバイル Suica、じゃらん、楽天トラベル、Booking.com、Airbnb、ANA、JAL、えきねっと、スマート EX、ぐるなび、食べログ、Steam、Nintendo、PlayStation、楽天銀行、SBI 新生銀行、au じぶん銀行、住信 SBI ネット銀行、三菱 UFJ 銀行、みずほ銀行、ゆうちょ銀行。定期便、サブスク更新、請求、入金、カード利用通知、宣伝は数えない。App Store と Google Play は更新の領収書と件名が同じなので外した。本人の受信箱 365 日分で実測し、拾ったのはすべて本物の取引で、宣伝の混入は 0。

### どう判断するか

- 加入時に 90 日の足跡を測り、その人が実際に使っている源だけを見張りに使う（Drive を使わない人の Drive の沈黙で発火したら事故）。使える源が無い人は「見張れない」と本人に告げ、Google の無効化通知だけを待つ。
- 沈黙の日数は「使える源のすべてが止まっている日数」。買い物の通知は弱い源で、Google 上の本人の活動が 60 日止まれば通知が続いていても確認者に問う（第三者でも正規の通知を届けられるため）。
- 状態: いつもどおり → 沈黙 30 日（気にかける、誰にも連絡しない）→ 沈黙 60 日（確認者に問う）→ 猶予 14 日 → 発火 → 最後の通知と 7 日のブレーキ → 執行 → 完了。どの段階でも本人の動きが見えたら最初に戻る。確認者の誰かが「取れた」と答えても戻る。
- 説明が要るとき（30 日を越えたとき）は、ADK の調査係が読み取り専用のツール 4 つ（源ごとの最終日と回数、予定の題名、買い物の内訳、足したサービスの公開活動）を全部呼んで手掛かりを集め、判断係が見立てと「待つ日数（0〜30）」を返す。縮める提案は状態機械が無視する。
- 確認者に見せる文面は「事実（機械が数えたもの。LLM を通さない）＋ 見立て（Gemini）」。見立ては URL、命令形、死亡の断定、「執行せよ」を含む文を落としてから載せる。

### 確認者への問い

署名（HMAC）つきの一問リンク。「本人と連絡が取れますか」に「取れた／取れない」の二択だけ。何を渡すか消すかは聞かない。トークンは URL の # 以降で渡し、サーバのログに残らない。2 人以上が「取れない」と答え、かつ猶予 14 日が過ぎて初めて発火する。

## 6. 執行

1. 発火したら本人へ最後の通知を送り、7 日待つ。その間に活動が一つでも見えたら止める。
2. 執行の直前にもう一度票を数え直し、2 人未満なら執行しない。
3. 計画: 止める（解約・連携解除）→ 渡す（存在を伝える、引き継ぐ）→ ハブは最後。各操作は決定的なポリシーゲートを通り、判定はハッシュ鎖で追記専用バケットに残る。
4. 封印した資格情報がある人の執行は Confidential Space の中だけ。Cloud Run は VM を起こすだけで、開ける権限を持たない。enclave は attestation → STS → KMS 復号を経て、開いた資格情報をメモリの中だけで使い、proof（SHA-256）だけを監査に残す（アカウント ID を手紙に差し込む処理は未実装）。VM は終わったら消す。
5. 遺族へのご報告を書く。何を止め、何を渡し、何を触らなかったか。あとがきは「本人からのことば」としてここで初めて開く。個人情報は Sensitive Data Protection で伏せる。
6. 完了したら以後は何もしない。enclave が一過性の理由で失敗したときは完了にせず、翌日やり直す。

いまの限界: 各社の解約手続きの自動化は未実装で、解約は依頼メールの作成まで。確認者への送信元（SMTP か Workspace の委任）は未設定で、本番では outbox に残る。

## 9. データの扱い

- 受信箱の本文を読むのは棚卸しの一回だけ。読み終えたらトークンを revoke する。本文は保存しない。
- 見張りは日時と、差出人ドメインと件名の型だけ。件名は判定に使うだけで保存しない。
- 地図・遺志・状態は利用者ごとの置き場に分け、セッションはメールアドレスを署名して持つ。他人の置き場には届かない。
- 封印した資格情報はサーバでは暗号文のみ。平文はブラウザと enclave の中だけ。
- LLM に渡すのは、棚卸しの本文（一回）と、見張りの事実・予定の題名・通知の内訳。Google Cloud の生成 AI はお客様データを学習に使わない。

## 10. 審査員・第三者が確かめる方法

- 審査用アカウント（ID とパスワード、Google ログイン不要）で入ると、架空の山田太郎の地図・遺志・確認者・あとがき・見張りの状態が入った状態で始まる。「初期化して入る」で戻せる。
- ログイン不要のデモ 3 つ: 「いま走らせる」（棚卸しエージェントが受信箱 72 通を本当に読み、注入メールを報告する様子を実況。約 3 分）、「通してみる」（82 日を数秒に圧縮。調べに行く手順、Gemini の見立て、ゲートの拒否、執行、ご報告）、「本物の enclave で開ける」（Confidential VM を起こして封印を開ける。約 5 分。digest と proof が出る）。
- 検査はすべて `tests/` にあり、本番に対して流せる。
